# Тестовые кейсы для метрик компонентов

## Описание

Данный документ описывает тестовые кейсы для проверки метрик выполнения компонентов на диаграмме под нагрузкой.

## Тестовые кейсы

### Кейс 1: Время выполнения компонента
**Цель:** Измерить время выполнения каждого компонента на диаграмме

**Шаги:**
1. Загрузить проект `project_for_component_test.zip`
2. Запустить процесс с диаграммой, содержащей несколько компонентов
3. Зафиксировать время начала и окончания выполнения каждого компонента
4. Вычислить длительность выполнения каждого компонента

**Ожидаемый результат:**
- Получены метрики времени выполнения для каждого компонента
- Данные сохранены в CSV/JSON формате для анализа

**Метрики:**
- `component_name` - название компонента
- `start_time` - время начала выполнения
- `end_time` - время окончания выполнения
- `duration_ms` - длительность выполнения в миллисекундах

---

### Кейс 2: Промежуток между выполнением компонентов
**Цель:** Измерить интервал времени между завершением одного компонента и началом следующего

**Шаги:**
1. Запустить процесс с последовательной цепочкой компонентов
2. Зафиксировать время завершения каждого компонента
3. Зафиксировать время начала следующего компонента
4. Вычислить промежуток между компонентами

**Ожидаемый результат:**
- Получены метрики интервалов между компонентами
- Определены узкие места в цепочке выполнения

**Метрики:**
- `previous_component` - предыдущий компонент
- `next_component` - следующий компонент
- `interval_ms` - промежуток времени в миллисекундах

---

### Кейс 3: Параллельное выполнение компонентов
**Цель:** Проверить поведение компонентов при параллельных запросах

**Шаги:**
1. Запустить несколько параллельных запросов к процессу
2. Отследить выполнение компонентов для каждого запроса
3. Проанализировать влияние параллелизма на время выполнения

**Ожидаемый результат:**
- Определено влияние параллельных запросов на производительность
- Выявлены компоненты, которые замедляются при нагрузке

**Метрики:**
- `request_id` - идентификатор запроса
- `component_name` - название компонента
- `duration_ms` - длительность выполнения
- `concurrent_requests` - количество параллельных запросов

---

### Кейс 4: Общее время выполнения диаграммы
**Цель:** Измерить суммарное время выполнения всех компонентов на диаграмме

**Шаги:**
1. Запустить процесс с полной диаграммой
2. Зафиксировать время начала первого компонента
3. Зафиксировать время завершения последнего компонента
4. Вычислить общее время выполнения

**Ожидаемый результат:**
- Получена метрика общего времени выполнения диаграммы
- Определены компоненты, занимающие наибольшее время

**Метрики:**
- `diagram_name` - название диаграммы
- `total_duration_ms` - общее время выполнения
- `components_count` - количество компонентов
- `average_component_duration_ms` - среднее время выполнения компонента

---

## Формат данных

Все метрики должны сохраняться в структурированном формате (CSV/JSON) для последующего анализа.

### Пример структуры данных:

```json
{
  "request_id": "uuid",
  "diagram_name": "test_diagram",
  "components": [
    {
      "component_name": "component_1",
      "start_time": "2025-01-19T16:30:00.000Z",
      "end_time": "2025-01-19T16:30:01.500Z",
      "duration_ms": 1500
    },
    {
      "component_name": "component_2",
      "start_time": "2025-01-19T16:30:01.600Z",
      "end_time": "2025-01-19T16:30:02.800Z",
      "duration_ms": 1200,
      "interval_from_previous_ms": 100
    }
  ],
  "total_duration_ms": 2800
}
```
